# Harness integration survey for ADRL (2026-09-03)

## 1. Scope and method

This survey asks, for every coding harness a large enterprise's teams might run in 2026, whether a harness-side routing and privacy proxy (ADRL) can be inserted between the harness and the model, and what it would see. The eight questions per harness are: (1) wire protocol to the model, (2) the exact setting that repoints the harness at a gateway, (3) identity signals on the wire, (4) hook or plugin surfaces, (5) custom headers, (6) sandboxing, (7) whether utility calls share the endpoint, (8) known constraints, plus licence and enterprise status.

Evidence tags: `[source: title, URL, fetched]` means I fetched the page today; `[source: ..., search-only]` means the claim comes from a search snippet I did not open. Where a page redirected, 404ed, or returned no content, I say so. The web-search budget ran out near the end; three follow-up questions (Codex cloud custom providers, Copilot coding-agent BYOK, Cursor's enterprise network page) were therefore answered by fetch only or marked as not found.

What ADRL needs from a harness, per the register: a base-URL or gateway setting (FND-001 removal test), a wire protocol it has a profile for (SEM-007: only `anthropic-messages-v1` exists), a session and agent identity signal (SEM-002: header first, then `metadata.user_id`, then a per-connection fallback), a way to tell request classes apart (SEM-001: user turn, continuation, utility, subagent, pre-warm, passthrough), and a way to surface a recoverable, protocol-conformant error (SAF-004, CAS-007).

## 2. Per-harness findings

### 2.1 Claude Code (CLI, VS Code, JetBrains, desktop app, GitHub Actions, Agent SDK)

**Protocol.** Anthropic Messages on `/v1/messages` and optional `/v1/messages/count_tokens`; Bedrock InvokeModel and Google Agent Platform rawPredict are alternative client formats selected by `CLAUDE_CODE_USE_BEDROCK=1` and `CLAUDE_CODE_USE_VERTEX=1`. Inference posts to `/v1/messages?beta=true`, so match on path. [source: Gateway protocol reference, https://code.claude.com/docs/en/llm-gateway-protocol, fetched]

**Repointing.** `ANTHROPIC_BASE_URL` for the Messages format; `ANTHROPIC_BEDROCK_BASE_URL`, `ANTHROPIC_VERTEX_BASE_URL`, `ANTHROPIC_FOUNDRY_BASE_URL`, `ANTHROPIC_AWS_BASE_URL` for provider formats. Credential goes in `ANTHROPIC_AUTH_TOKEN` (bearer) or `ANTHROPIC_API_KEY` (`x-api-key`), or an `apiKeyHelper`. Administrators distribute these through managed settings or MDM. [source: Connect Claude Code to an LLM gateway, https://code.claude.com/docs/en/llm-gateway-connect, fetched] Surfaces differ: the VS Code extension reads `claudeCode.environmentVariables`; the desktop app ignores `ANTHROPIC_BASE_URL` and reads `inferenceProvider: gateway` plus `inferenceGatewayBaseUrl` from its managed configuration; GitHub Actions reads `ANTHROPIC_BASE_URL` and `ANTHROPIC_CUSTOM_HEADERS` from the workflow `env`; the Agent SDK has no gateway option and passes `env` to the spawned process (TypeScript `options.env` replaces the environment, Python merges); Slack and web sessions "always use Anthropic's API" and cannot be gatewayed. [source: same page, fetched; Deploy Claude Desktop on 3P with an LLM gateway, https://claude.com/docs/third-party/claude-desktop/gateway, fetched] The JetBrains plugin runs the `claude` CLI in the IDE terminal and has no gateway setting of its own. [source: JetBrains IDEs, https://code.claude.com/docs/en/jetbrains, fetched]

**Identity.** `x-claude-code-session-id` on every request; `x-claude-code-agent-id` only on subagent requests; `x-claude-code-parent-agent-id` for nested agents. Subagent IDs are fresh per spawn, agent-team teammates reuse a stable name-based ID, and "don't treat the agent ID header as a user identifier". [source: Gateway protocol reference, fetched] The desktop app in SSO mode forwards the IdP token verbatim as `Authorization: Bearer`, so per-user identity is available at the gateway from the JWT `sub` or `oid` claim. [source: Claude Desktop gateway page, fetched]

**Hooks.** Command, http, mcp_tool, prompt and agent hook types over a large event list including `PreToolUse`, `PostToolUse`, `PostToolBatch`, `SubagentStart`, `SubagentStop`, `PreCompact`, `PostCompact`, `PreModelSwitch`, `SessionStart`, `Stop`; input carries `session_id`, `transcript_path`, `agent_id`, `tool_use_id`; exit code 2 or `permissionDecision: deny` blocks. [source: Hooks reference, https://code.claude.com/docs/en/hooks, fetched] The Agent SDK exposes the same events as callbacks, with session hooks not available in Python. [source: Agent SDK hooks, https://code.claude.com/docs/en/agent-sdk/hooks, fetched]

**Custom headers.** `ANTHROPIC_CUSTOM_HEADERS` (`Name: Value`, newline-separated, v2.1.227+); the desktop app has `inferenceCustomHeaders`. [source: Environment variables, https://code.claude.com/docs/en/env-vars, fetched; Claude Desktop gateway page, fetched]

**Sandbox.** Bash sandbox on macOS Seatbelt and Linux bubblewrap plus socat, with `sandbox.network.allowedDomains`, a sandbox proxy that can terminate TLS (`network.tlsTerminate`) and substitute masked credentials. Native Windows unsupported. [source: Configure the sandboxed Bash tool, https://code.claude.com/docs/en/sandboxing, fetched]

**Utility calls.** Background tasks use the model behind `ANTHROPIC_DEFAULT_HAIKU_MODEL` (the older `ANTHROPIC_SMALL_FAST_MODEL` is deprecated) on the same base URL. [source: Environment variables, fetched] Compaction depends on the gateway relaying the upstream context-limit error unmodified; a gateway that rewrites it in its own words defeats auto-compaction. [source: Connect page troubleshooting table, fetched]

**Constraints.** Fast-mode availability and the WebFetch domain safety check call `api.anthropic.com` directly and ignore `ANTHROPIC_BASE_URL`; telemetry, version checks and release notes also go outside the gateway unless `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`. `anthropic-beta` and `anthropic-version` must be forwarded verbatim; body rewriting for content inspection "breaks the pairing the same way stripping does"; a rejected `thinking` or `cache_control` field makes the client "disable the rejected capability for the rest of the conversation"; SSE `ping` events feed a 300-second byte watchdog. Model discovery is `GET /v1/models?limit=1000` with a 3-second timeout, redirects treated as failure. [source: Gateway protocol reference, fetched; Data usage, https://code.claude.com/docs/en/data-usage, fetched] A community bug reports the VS Code extension showing a login screen even when `ANTHROPIC_BASE_URL` is in managed settings. [source: GitHub issue #8522, https://github.com/anthropics/claude-code/issues/8522, search-only]

**Licence and enterprise.** Agent SDK use is governed by Anthropic's Commercial Terms. [source: Agent SDK overview, https://code.claude.com/docs/en/agent-sdk/overview, fetched] The GitHub repo fetch reported a LICENSE.md described as MIT; I could not confirm that the CLI bundle itself is under that licence, so treat the CLI as proprietary until checked. [source: anthropics/claude-code, https://github.com/anthropics/claude-code, fetched, uncertain] Enterprise path: Claude apps gateway, a self-hosted server inside the `claude` binary that fronts Bedrock, Claude Platform on AWS, Google Agent Platform, Foundry or the Anthropic API with SSO, per-group managed settings and OTLP export, and serves `GET /protocol`. [source: Claude apps gateway, https://code.claude.com/docs/en/claude-apps-gateway, fetched]

### 2.2 OpenAI Codex (CLI, IDE extension, Codex cloud, SDK, app server)

**Protocol.** OpenAI Responses only: `wire_api` documents `responses` as "the only supported value". [source: Config reference, https://learn.chatgpt.com/docs/config-file/config-reference, fetched] Codex appends `/responses` to `base_url`. [source: Merge gateway Codex page, https://docs.merge.dev/merge-gateway/coding-agents/codex, fetched]

**Repointing.** `[model_providers.<id>]` with `name`, `base_url`, `env_key`, `wire_api`, `http_headers`, `env_http_headers`, `query_params`, `request_max_retries`, `stream_idle_timeout_ms` (default 300000), `requires_openai_auth`; top-level `model_provider` selects it; `OPENAI_BASE_URL` overrides the built-in provider. [source: Config reference, fetched; Advanced config, https://learn.chatgpt.com/docs/config-file/config-advanced, fetched]

**Identity.** Codex sends `originator: codex_cli_rs`, a `User-Agent` of `codex_cli_rs/<version>`, `session_id` derived from the conversation id, `x-client-request-id`, `x-openai-subagent`, `x-codex-turn-metadata`, `x-codex-turn-state`; body carries `prompt_cache_key`, `store`, `include`, `reasoning`. [source: Codex-Manager header comparison report, https://github.com/qxcnm/Codex-Manager/blob/main/docs/zh-CN/report/..., fetched, third-party] OpenAI's own gateway rejected the underscore header and the client was asked to switch to `session-id`. [source: openai/codex issue #11732, https://github.com/openai/codex/issues/11732, fetched] OTEL export tags `auth_mode`, `originator`, `session_source`. [source: Advanced config, fetched]

**Hooks.** Events `SessionStart`, `SessionEnd`, `SubagentStart`, `SubagentStop`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `UserPromptSubmit`, `Stop`, `Interrupt`; discovered in `~/.codex/hooks.json`, `~/.codex/config.toml`, `<repo>/.codex/hooks.json`; input has `session_id`, `cwd`, `transcript_path`, `model`, `turn_id`; deny via `permissionDecision: "deny"` or exit 2. [source: Hooks, https://learn.chatgpt.com/docs/hooks, fetched]

**Custom headers.** Yes, `http_headers` and `env_http_headers`. **Sandbox.** macOS Seatbelt, Linux bubblewrap, native Windows sandbox or WSL2; the sandbox "does not restrict the model's API calls themselves". `sandbox_mode` is `read-only`, `workspace-write` or `danger-full-access`. [source: Sandboxing, https://learn.chatgpt.com/docs/sandboxing, fetched; Config reference, fetched]

**Utility calls and constraints.** Not documented separately; compaction uses the same provider. Codex cloud runs on OpenAI infrastructure and I found no documentation that a cloud environment honours `model_providers`; treat cloud as un-gatewayable until shown otherwise (documentation not found). Enterprise administration covers plugin allowlists, roles, workload identity and audit routing but the fetched page did not list enforceable `requirements.toml` keys for `base_url`. [source: Administration, https://learn.chatgpt.com/docs/administration, fetched]

**Licence.** Apache-2.0. [source: openai/codex, https://github.com/openai/codex, fetched] Note the docs domain moved from developers.openai.com to learn.chatgpt.com (308 redirects observed today).

### 2.3 GitHub Copilot (CLI, VS Code agent mode, Copilot app, coding agent, SDK)

**Protocol.** Native Copilot traffic goes to `*.githubcopilot.com` and `copilot-proxy.githubusercontent.com` and cannot be repointed. [source: Allowlist reference, https://docs.github.com/en/copilot/reference/allowlist-reference, fetched] With BYOK the protocol is the provider's: SDK `wireApi` is `completions` or `responses`, provider `type` is `openai`, `azure` or `anthropic`. [source: Copilot SDK BYOK, https://docs.github.com/en/copilot/how-tos/copilot-sdk/auth/byok, fetched]

**Repointing.** CLI: `COPILOT_PROVIDER_BASE_URL` (required), `COPILOT_PROVIDER_TYPE` (`openai` default, `azure`, `anthropic`), `COPILOT_PROVIDER_API_KEY`, `COPILOT_MODEL`; models "must support tool calling and streaming". [source: Using your own LLM models in Copilot CLI, https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models, fetched] Enterprise admins add custom models from Anthropic, AWS Bedrock, Google AI Studio, Microsoft Foundry, OpenAI, "OpenAI-compatible providers" and xAI, surfaced to Chat, CLI and IDEs; the page does not mention the coding agent. [source: Enabling custom models, https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/enable-custom-models, fetched] VS Code BYOK is available to Business and Enterprise in Chat including plan and custom agents, excluding completions. [source: GitHub changelog 2026-04-22, https://github.blog/changelog/2026-04-22-bring-your-own-language-model-key-in-vs-code-now-available/, fetched] The Copilot app accepts "any OpenAI-compatible endpoint" with endpoint and key. [source: GitHub changelog 2026-06-23, https://github.blog/changelog/2026-06-23-github-copilot-app-support-for-byok/, fetched] The coding agent runs on GitHub Actions and its page has no custom endpoint option. [source: About coding agent, https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-coding-agent, fetched]

**Identity.** With a BYOK custom endpoint Copilot sends only `Authorization: Bearer <apiKey>`; Kong attributes per developer by issuing each one a consumer-scoped key. [source: Kong GitHub Copilot BYOK cookbook, https://developer.konghq.com/cookbooks/github-copilot-byok/, fetched] No session or agent header is documented.

**Hooks.** CLI events `sessionStart`, `sessionEnd`, `userPromptSubmitted`, `preToolUse`, `postToolUse`, `errorOccurred`, `agentStop`; files in `.github/hooks/` or `~/.copilot/hooks/`; blocking semantics not described. [source: Use hooks, https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-hooks, fetched] **Custom headers.** Not documented for BYOK. **Sandbox.** CLI has local sandboxing and `copilot --cloud`. [source: Use Copilot CLI, https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-copilot-cli, fetched] **Constraints.** BYOK bypasses GitHub telemetry and premium quotas. [source: SDK BYOK, fetched] Proxy and custom-certificate guidance exists per IDE; nothing about certificate pinning. [source: Configure network settings, https://docs.github.com/en/copilot/how-tos/configure-personal-settings/configure-network-settings, fetched] **Licence.** Proprietary service; the copilot-cli repo has a LICENSE.md but the fetch could not confirm the CLI source is there. [source: github/copilot-cli, https://github.com/github/copilot-cli, fetched, uncertain]

### 2.4 Cursor (editor agent, CLI, cloud agents)

**Protocol and repointing.** Custom keys for OpenAI, Anthropic, Google, Azure OpenAI and Bedrock "only work with chat models"; keys are "transmitted with each request through Cursor's servers", so the developer's machine never talks to the gateway directly. [source: Custom API keys, https://cursor.com/docs/settings/api-keys, fetched] An "Override OpenAI Base URL" toggle exists and only applies to features on standard chat completions; users report it breaking Anthropic models with 422s. [source: Cursor community forum and third-party guides, https://forum.cursor.com/t/openai-api-and-override-base-url-values/148140, search-only] The CLI documents `--model` and `--sandbox` but no base URL. [source: Cursor CLI overview, https://cursor.com/docs/cli/overview, fetched] Cloud agents run in Cursor-managed VMs; the page does not say custom keys apply there. [source: Cloud agents, https://cursor.com/docs/cloud-agent, fetched] Cursor's enterprise network page returned 404 today.

**Identity.** Hook payloads carry `conversation_id`, `generation_id`, `model`, `user_email`, `transcript_path`; nothing is documented on the model wire. **Hooks.** `sessionStart`, `preToolUse`, `postToolUse`, `subagentStart`, `beforeShellExecution`, `beforeMCPExecution`, `beforeSubmitPrompt`, `preCompact`, `stop`, `afterAgentResponse`; enterprise-wide `hooks.json` under `/Library/Application Support/Cursor/`, `/etc/cursor/`, `C:\ProgramData\Cursor\`, plus dashboard-distributed team hooks; exit 2 blocks, `failClosed` available. [source: Agent hooks, https://cursor.com/docs/agent/hooks, fetched] **Sandbox.** Cloud VMs with outbound-domain restriction; CLI `--sandbox`. **Constraints.** Custom keys void Cursor's zero-data-retention. Enterprise offers privacy mode, SCIM, audit logs, OTLP export, PrivateLink, but no customer gateway. [source: Enterprise, https://cursor.com/docs/enterprise, fetched] **Licence.** Proprietary.

### 2.5 Gemini CLI, Antigravity, Jules

**Gemini CLI.** Protocol is the Gemini API or Vertex. `GOOGLE_GEMINI_BASE_URL` "Overrides the default base URL for Gemini API requests" and `GOOGLE_VERTEX_BASE_URL` does the same for Vertex; settings layers include `/etc/gemini-cli/system-defaults.json` and `/etc/gemini-cli/settings.json`; `tools.sandbox` accepts `docker`, `podman`, `lxc`; telemetry via `GEMINI_TELEMETRY_*`. [source: Configuration reference, https://geminicli.com/docs/reference/configuration/, fetched] Hooks `SessionStart`, `SessionEnd`, `BeforeAgent`, `AfterAgent`, `BeforeModel`, `AfterModel`, `BeforeToolSelection`, `BeforeTool`, `AfterTool`, `PreCompress`, `Notification`, run synchronously, exit 2 blocks; `BeforeModel`/`AfterModel` are the only hooks in this survey that fire around the model call itself. [source: Hooks, https://geminicli.com/docs/hooks/, fetched] Sandbox: macOS `SEATBELT_PROFILE` with `*-proxied` variants, Docker, Podman, gVisor, LXC. [source: Sandbox, https://geminicli.com/docs/cli/sandbox/, fetched] LiteLLM fronts it with `GOOGLE_GEMINI_BASE_URL`. [source: LiteLLM Gemini CLI tutorial, https://docs.litellm.ai/docs/tutorials/litellm_gemini_cli, search-only] A request for corporate-proxy and gateway documentation was closed as not planned. [source: gemini-cli issue #15543, https://github.com/google-gemini/gemini-cli/issues/15543, fetched] Custom headers and session headers: not documented. Licence Apache-2.0. [source: google-gemini/gemini-cli, https://github.com/google-gemini/gemini-cli, fetched]

**Antigravity.** Five surfaces (desktop, CLI, SDK, Managed Agents API, Enterprise Agent Platform). [source: Getting started, https://antigravity.google/docs/getting-started, fetched] Enterprise routes through the customer's Google Cloud project on the Gemini Enterprise Agent Platform with regional endpoints and VPC-SC; "custom model endpoints and private gateways are not mentioned". [source: Enterprise, https://antigravity.google/docs/enterprise/, fetched] Models page lists Gemini, Claude and GPT-OSS with no BYOK. [source: Models, https://antigravity.google/docs/models/, fetched] A forum thread attempting `antigravity.ai.provider: openai-compatible` reports it does not work and has no official reply. [source: Google AI forum, https://discuss.ai.google.dev/t/.../168654, fetched] Hooks `PreToolUse`, `PostToolUse`, `PreInvocation`, `PostInvocation`, `Stop` in `hooks.json` with `conversationId` and `modelName`; `PreToolUse` supports `deny`. [source: Hooks, https://antigravity.google/docs/hooks, fetched] Proprietary.

**Jules.** Runs in a Google VM; REST API in alpha with Source, Session, Activity and `X-Goog-Api-Key`; no model or endpoint configuration. [source: Jules API, https://developers.google.com/jules/api, fetched; Jules docs, https://jules.google/docs/, fetched] Not gatewayable.

### 2.6 Amazon Kiro and Q Developer CLI

Amazon Q Developer CLI "has been rebranded to Kiro"; the Q console is the Kiro console. [source: Upgrade to Kiro, https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/upgrade-to-kiro.html, fetched] Kiro is "powered by Amazon Bedrock" with a fixed catalogue (Claude, GPT-5.6, DeepSeek, MiniMax, GLM, Qwen); no BYOK or custom endpoint. [source: Models, https://kiro.dev/docs/models/, fetched] The BYOK request is closed as duplicate and unimplemented. [source: kirodotdev/Kiro issue #9367, fetched] Egress goes to `q.<region>.amazonaws.com`, `runtime.<region>.kiro.dev`, `management.<region>.kiro.dev`, `telemetry.<region>.kiro.dev`; `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` are honoured; browser sign-in bypasses the proxy. [source: Firewalls, proxies and data perimeters, https://kiro.dev/docs/privacy-and-security/firewalls/, fetched] PrivateLink endpoints `com.amazonaws.<region>.q` and `.codewhisperer`. [source: VPC endpoints, https://kiro.dev/docs/privacy-and-security/vpc-endpoints/, fetched] Hooks `PromptSubmit`, `AgentStop`, `SessionStart`, `AgentSpawn`, `PreToolUse`, `PostToolUse`, `PreTaskExecution`, `PostTaskExecution`; only `PromptSubmit`, `PreToolUse`, `PreTaskExecution` block. [source: Hooks, https://kiro.dev/docs/hooks/, fetched] Enterprise model allowlist via the Kiro console. [source: Model governance, https://kiro.dev/docs/enterprise/governance/model/, fetched] Proprietary service; the wire protocol is AWS-signed and not an ADRL profile.

### 2.8 OpenCode

[source: Plugins, https://opencode.ai/docs/plugins/, fetched] Enterprise plan: central config, SSO, "use only your internal AI gateway" and disable other providers; "all processing happens locally or through direct API calls to your AI provider". [source: Enterprise, https://opencode.ai/docs/enterprise/, fetched] Sandbox: experimental `experimental.policies`; Docker and Vercel sandbox recipes exist. [source: Policies and Docker docs, search-only] Licence MIT. [source: anomalyco/opencode, https://github.com/anomalyco/opencode, fetched]

### 2.11 Amp

Amp is a hosted multi-model agent ("GPT-5.6, Claude Fable 5.1, fast models") that selects models itself; there is no documented custom endpoint or base URL, and settings keys cover `amp.mcpServers`, `amp.tools.disable`, `amp.admin.compatibilityDate` and similar. [source: Amp manual, https://ampcode.com/manual, fetched; CLI settings, https://ampcode.com/docs/cli/settings, fetched] A third-party connector writes an undocumented `amp.url` setting. [source: ampcode-connector README, search-only] Plugin API has `tool.call`, `tool.result`, `session.start`, `agent.start`, `agent.end` and `createWebhook()`; "plugins cannot see or modify model requests directly". [source: Plugin API, https://ampcode.com/docs/plugin-api, fetched] Cloud "Orbs" are per-thread machines. The enterprise page requires sign-in. Proprietary; not gatewayable at the model layer.

### 2.12 Zed agent

## 3. Enterprise "bring your own gateway" patterns

Three patterns recur. First, a plain base-URL override where the harness speaks its native protocol to a URL the enterprise owns: Claude Code, Codex, Copilot BYOK, OpenCode, Aider, Cline, Zed, Junie, Gemini CLI. Second, a vendor-shipped gateway product: Claude apps gateway (self-hosted, SSO, serves `/protocol`), OpenCode Enterprise central config, Copilot enterprise custom models. Third, vendor-hosted agents where the gateway can only sit inside the vendor's cloud or not at all: Cursor cloud agents, Copilot coding agent, Codex cloud, Devin, Jules, Amp, Kiro. Independent gateways (LiteLLM, Kong, Portkey, Bifrost, Merge, TrueFoundry, Cloudflare and Vercel AI Gateway) all front the first pattern by exposing Anthropic, OpenAI and Gemini-shaped endpoints.
