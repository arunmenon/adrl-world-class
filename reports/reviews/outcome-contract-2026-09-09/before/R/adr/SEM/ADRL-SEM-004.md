## Decision

Cosmetic utility calls (session title, next-command suggestion, topic detection) may use a small local model; context-bearing utility calls (compaction and any request whose output re-enters the transcript) inherit the session's rung and gate state; protocol and unknown calls pass through unchanged subject to SAF gates.

1. A utility call is *cosmetic* when its output is displayed to the developer or consumed by ADRL but never fed back into a model context; it is *context-bearing* when its output becomes part of a later request (compaction summaries, generated system reminders).
2. On a privacy-pinned session every utility call, cosmetic or not, is served locally or dropped; a cosmetic call that cannot be served locally is answered with an empty-but-valid response rather than forwarded.
3. Utility calls are fingerprinted by request shape (system-prompt template, `max_tokens`, absence of the harness tool list), not by requested model name.

## Context and rationale

The harness makes small calls that are not your work: naming a session, suggesting the next command, deciding whether a message starts a new topic, summarising for compaction. Corpus finding: these run on Opus/Sonnet with tiny token budgets, not on a cheap model, so they are fingerprinted by shape rather than model name.

The amendment splits the class on the one property that matters for both quality and privacy: does the output go back into the model? A title generated by a 3B local model is a cosmetic difference nobody will notice. A *compaction summary* generated by a 3B local model becomes the frontier model's entire memory of the first hour of the session; a weak summary degrades every subsequent turn, in a way the developer will feel and could never attribute — precisely the failure FND-001 forbids. Compaction also carries the full transcript, so on a pinned session it is a content-bearing exfiltration path, and if the local rung cannot hold the transcript the SAF-005 block can leave the session unable to compact at all. The split lets the cheap win (titles, suggestions) be taken without the expensive loss.

## Adversarial review (2026-09-02)

### Steelman
Housekeeping is the cleanest possible local-model workload: short, structured, low-stakes, and invisible to the developer. Serving it locally is pure saving with no quality exposure, and the shape fingerprint is robust against the harness changing which cloud model it asks for. Passing unknown calls through unchanged is the correct fail-safe for a taxonomy known to be incomplete.

### Attacks
1. **Compaction is not housekeeping.** Claude Code compacts by asking a model to summarise the transcript and then replacing the transcript with the summary. If that summary comes from a small local model, every later frontier turn reasons from a worse memory. The developer sees "Claude forgot what we agreed" and has no way to know a local model wrote the summary. This is a quality regression hidden inside a cost optimisation — and the register's own "utility = housekeeping = local" framing invites it.
2. **Utility calls carry the conversation.** Title generation includes the user's message; topic detection includes recent turns; compaction includes everything. On a pinned session these are content-bearing requests; "may use a small local model" is permissive where it must be mandatory, and "protocol and unknown calls pass through unchanged" sends an *unknown* content-bearing call to the cloud by default.
3. **The pre-warm request fingerprints as a utility call.** `max_tokens: 1` is the classic utility signature; the pre-warm has `max_tokens: 1` *and* the full tool list. Fingerprinting on `max_tokens` alone files the frontier cache-warmer as housekeeping and sends it to a local model, so the frontier cache is cold when the real turn arrives. Sub-clause 3's "absence of the harness tool list" is there to prevent this.
4. **Topic detection is a signal ADRL should read, not route.** Sung's trace shows the harness already asks "isNewTopic" with a 2–3-word title. That is a free, harness-produced episode-boundary candidate for SEM-005. Treating it as a utility call to be served cheaply and discarded wastes it.
5. **Local availability on a pinned session.** If the local rung is down and the session is pinned, a cosmetic utility call has three options: forward to cloud (breaks the pin), fail with an error (the harness may surface a spurious error or retry), or answer with a valid empty result. The decision does not say; sub-clause 2 chooses the third because Claude Code treats the title/suggestion calls as best-effort.
6. **Maturity mismatch.** D3 is claimed, but the corpus finding says the original assumption (utility calls go to a cheap model) was wrong, and the shape fingerprints were re-derived after that. Shadow evidence for the *new* fingerprints and for the cosmetic/context-bearing split does not yet exist.

### Evidence

- Anthropic, "Compaction" (Claude Platform docs; title from search, not fetched) — server-side/context compaction is a documented feature whose output replaces context; bears on attack 1 — https://platform.claude.com/docs/en/build-with-claude/compaction
- Anthropic, "Connect Claude Code to an LLM gateway" (Claude Code docs) — auto-compaction is triggered by a recognised too-long error and `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is clamped to at least 100,000 tokens; bears on attack 1 and the SAF-005 deadlock — https://code.claude.com/docs/en/llm-gateway-connect
- Anthropic, "Prompt caching" (Claude Platform docs) — per-model cache (implied by per-model rules, not stated outright); a pre-warm served by a different model warms nothing for the frontier; bears on attack 3 — https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- anthropics/claude-code, issue #10548 "[FEATURE] auto-compact with Haiku" (GitHub; title from search) — community request to run compaction on a cheaper model, indicating the quality/cost trade-off is contested even inside the vendor's user base; bears on attack 1 — https://github.com/anthropics/claude-code/issues/10548

### Verdict
**AMEND.** Attacks 1 and 2 land squarely: the decision treats a class as homogeneous when its members differ on the two properties the register cares most about (quality exposure and privacy exposure). Attack 3 is answered by the fingerprint clause. Attack 4 is a cross-bucket opportunity recorded in SEM-005. Attack 5 is answered by sub-clause 2. Attack 6 lowers the maturity recommendation. The verdict is amend rather than reject because the cosmetic half of the decision is exactly right and is the cheapest, safest local win in the system.

## Amendments applied

- Split "utility calls" into cosmetic (local permitted) and context-bearing (inherit session rung and gate state).
- Added "subject to SAF gates" to the passthrough clause.
- Added sub-clause 1 defining the split by whether output re-enters a model context.
- Added sub-clause 2 mandating local-or-empty for all utility calls on pinned sessions.
- Added sub-clause 3 fixing the fingerprint to shape including tool-list absence, excluding the pre-warm.
