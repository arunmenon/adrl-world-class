# Evidence loop, learning, RSI and experimental validity

Inspector: rv-evidence (Claude Fable 5.1). Snapshot: `adrl-review-fable-2026-09-08/snapshot` (register R, runtime C), frozen 2026-09-08T10:56Z. Read-only on both repositories. Offline checks ran in `disposable-evidence/` with the adrl-core venv and `PYTHONPATH` pointed at the disposable copy; the import path was asserted at `disposable-evidence/runtime/src/adrl/__init__.py`. Script and raw results are copied to `appendix/evidence-loop-check/`. Author claims were treated as hypotheses.

Path shorthand: `R/` = `snapshot/register/`, `C/` = `snapshot/runtime/`.

## 1. Headline

The runtime contains a well tested set of loop components, but they do not form a loop. The live proxy and cascade write outcome transitions as events typed `pending` and `closed_turn`, while the closer, the label deriver, the readiness counter, replay and the learning reader all look for events typed `outcome` carrying a `state` field. Driving the real composition offline with the lab's synthetic endpoint produced two decisions, one `closed_turn` event and one `pending` event per route; the closer saw zero routes in `closed_turn`, no route ever reached `closed_final` even when scanned thirty days later, readiness counted zero closed routes, and the learning reader saw both decisions as `pending`. No organic decision can currently become an attributed outcome, a label, or an eligible example through the served path. Every downstream link (tiers, dataset, estimator, abstention, artifacts, exploration) is real code with real unit tests, but the tests feed each component the shape it expects and never connect the producer to the consumer.

Three further gaps close the loop even if that split were fixed: no code produces a verifier-precision record, so T1 is unreachable and the holdout can never be built; every decision written since W7.0a carries `features-v2` while the only learning contract is `features-v1`, so the dataset builder, estimator and exploration channel refuse all organic rows; and late human corrections update the ledger label but never reach the learning example. The RSI links (champion and challenger, rollback, drift, cost of the improver) are absent from code and, in the blueprint, are stated as plans.

On experiments: every published count I could reconcile against raw JSON matched. The weaknesses are methodological, not arithmetic. No experiment in the register ran a model or a harness against a routing decision. The whole evidence chain from the first pilot to the planning starter pack recycles one task (`p01-template-repair-r2`) for the harness work and a synthetic Messages fixture for the routing work.

## 5. PRD, HLD and LLD assessment

The pack (`R/reports/lab/planning-starter-v1/assessment.md`, `contract.md`; `R/design/adrl-lab-planning-and-assessment-2026-09-08.md`) correctly separates three layers: deterministic constraints with an `indeterminate` outcome (`assessment.md:6-16`), a 0-3 expert rubric (`:18-30`), and later utility (`:40-45`). Bias controls are specified but not exercised: blinding and order randomisation (`:35-36`), judge calibration against a human set with known-defective controls (`:36-38`), a self-preference prohibition ("The generating model cannot certify its own work", `:38`), and a verbosity rule (`:30`). No reviewer, human or model, was assigned or run; no score exists anywhere in the pack; the author of the packs is the author of the rubric (`assessment.md:2-4`). The simulated rubric therefore implies nothing about reviewers having been assigned, and the pack does not claim they were.

Gaps in the rubric as drafted: score 0 conflates "contradicts supplied requirements" with "lacks usable evidence" (`assessment.md:22`), so the expert dimensions have no abstention level, which will bias any later inter-rater agreement figure; assessment cost is "when available" with no budget (`:45`).

Can a subjective score silently enter the objective or organic contract? Mostly no. `simulator` and `benchmark` sources map to T4 (`tiers.py:127-128`); only T1 enters the objective and holdout (`tiers.py:216-218, 242-246`; `dataset.py:293-297`); an unmeasured verifier caps at T2. The one gap is that `LedgerExampleReader` defaults every decision to `source="organic"` (`tiers.py:334,349-350`) and an outcome payload carrying `harness_reported_success` alone yields organic T3. A judge that writes such a payload into a live ledger would be read as organic proxy evidence. The lab is protected only because it writes to disposable temp ledgers (`C/docs/routing-lab.md:64-68`); `contract.md:43` states the rule but no code enforces it.

## 6. Findings

### 6.1 Observed defects

**D1. Live outcome events are invisible to every consumer that turns a decision into a label.** Severity critical. Confidence high. Files: `C/src/adrl/cascade/controller.py:199-207,278,320,361,637`; `C/src/adrl/proxy/pipeline.py:619-625`; consumers at `C/src/adrl/ledger/outcomes.py:81-89,112-122`, `labels.py:145,197-206`, `readiness.py:60-75`, `replay.py:44`, `verification.py:371-373`, `learning/tiers.py:342`. Claim: MEM-002 is "D2 Tested" for the state machine and the lab reports "ten distinct ADRL decision IDs" flowing through the path. Observation: the cascade writes `event_type="pending"` and `event_type="closed_turn"`; the consumers select `event_type='outcome'` and read `payload.state`. Evidence: offline check (`appendix/evidence-loop-check/results.json`, part A) on the real composition: event types `{closed_turn:1, pending:2, request:2, served:2}`, `routes_in_state(CLOSED_TURN)` = 0, closer closed 0 routes at +30 days, readiness `closed_final_count: 0`, reader states `pending`. Lab run-2 `events.jsonl` shows the same types. Consequence: no served decision can ever be counted, labelled, closed, verified against a `closed_turn` identity, or admitted to learning; every readiness number the product could publish from organic traffic is zero by construction, not by scarcity. Correction: emit `outcome` events with a `state` field from the cascade (or teach one shared reader both shapes with an upcaster), and add a contract test that drives the composed pipeline and asserts `Closer.scan` closes the route. Acceptance: a test in `tests/integration/e2e` that sends two user turns through `build_asgi(build_components(...))`, runs `Closer.scan`, and asserts one `closed_final` outcome and one label event for the first route; `tools/check_ledger_discipline.py` extended to fail if any producer writes an `OutcomeState` value as an `event_type`.

**D2. Rule health and trip-wire coverage read a third event shape that no producer writes.** Severity high. Confidence high. Files: `C/src/adrl/routing/rule_health.py:77-89`, `C/src/adrl/cascade/tripwires.py:441-460`; producer `run_demo.py:170-179` (register). Claim: "compute_rule_health demotes a rule at 0.60 precision" (`R/reports/adrl-routing-in-action-2026-09-08.md:39`). Observation: both readers select `event_type='closed_final'` with `verified`/`success` payload keys; the only writer of that shape is the demonstration script, which inserted invented rows with producer `synthetic-demo-only`. The closer writes `event_type='outcome'` with the label nested under `label`. The router computes rule health once at startup (`router.py:93-97`) from a table that will always be empty in production. Consequence: the self-correcting rule mechanism cannot fire on organic evidence. Correction: one outcome projection module consumed by all three readers. Acceptance: `compute_rule_health` demotes a band from events written by `Closer.close_route`, under test.

**D3. Late human corrections do not reach learning examples.** Severity high. Confidence high. Files: `C/src/adrl/learning/tiers.py:288-294,353-356`; `C/src/adrl/ledger/outcomes.py:262-278`. ### 6.4 Strategic disagreements

**S1. Building the learning stack ahead of the outcome pipe.** The learning package is the most thoroughly tested part of the runtime and the least reachable. Every hour spent on tiers, splits, estimators and abstention before D1, D6 and D7 are fixed produces code that cannot see a single organic row. I would freeze `adrl.learning` and spend the next slice on the outcome projection, the closer supervisor and a precision run.

**S2. "Autonomous RSI" is not on the path yet.** The improvement evaluator is a good offline A/B harness for operator candidates. Calling its single run an RSI step, or the W7.0a hand repair an adaptation, would overstate it; the register mostly avoids this, but the roadmap language around "improvement loops" should say that today the improver is a person.

**S3. Task diversity should come from other people's work, not more author prompts.** The 36 lexical prompts and 3 planning packs are useful mechanism probes and nothing more. The cheapest real signal is a second developer's organic session on a second repository with the verifier attached; it is worth more than another 240-cell matrix.
