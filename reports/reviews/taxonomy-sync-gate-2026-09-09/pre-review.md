## Blocking findings

- **B1. The wave cannot satisfy its own baseline rule as written.** The skill requires a snapshot before any edit, but the `begin` command does not exist until this wave writes it. Writing it is an edit. The plan must name the bootstrap path explicitly: before touching either repo, record a reconstructed baseline from real artifacts that already exist. For adrl-core that is a fresh run of the existing manifest function in the W0 runner plus the git head and porcelain status. For the register repo no prior manifest exists, so the baseline is git head, porcelain status, and a stdlib hash walk taken before the first edit. The first receipt must be labelled "reconstructed baseline" and must say why. If this ordering is not written into the packet, the tool's first ownership evidence contradicts the skill it ships with.

- **B2. The ownership mapping has no declared source for most input classes.** Module docstrings cover Python under src and tools. Tests, docs, config, api, artifacts, markdown skills and deleted files have no primary ADR anywhere. The check cannot derive ownership for a deleted file from a baseline that stores only hashes. Decide now: the closure record is a JSON file listing every changed, added or deleted path, its baseline and current hash, and its owning ADR IDs. The checker verifies coverage against the diff. It also verifies that each named ADR exists and contains a dated section linking that closure record. Recommend `begin` additionally captures the primary ADR ID of every Python file so deletions can be cross-checked against the author's claim.

- **B3. The receipt and evidence record are self-referential inputs.** If the receipt or the committed copy under reports is inside the hashed scope, the receipt can never match the tree it describes. Follow the W0 convention: the receipt is written outside both repos. A copy committed under reports is excluded from the manifest by declared path, and the receipt records that exclusion. The reviewer's record edit after the author's check will invalidate the receipt. That is correct behavior. The packet must state that a final check runs after the reviewer record lands.

- **B4. "Non-runtime docs need no rerun" is undefined without an input classification.** The W0 runner hashes docs, AGENTS, CLAUDE and README alongside src. The closure check must compare only runtime-relevant inputs against the cited runner manifest. Declare the split now. Runtime-relevant: src, tests, tools, config, api, pyproject and uv.lock. Non-runtime: docs, README, AGENTS, CLAUDE, gitignore and artifacts. The new CLI lands in tools, so this wave itself requires a runner rerun after the tool is written and before register updates. Sequence: baseline, write tool and tests, run the runner, then register and doc edits, then closure check, then review, then final check.

- **B5. Tool placement decides the test harness.** "Register tools" is ambiguous. The register repo has no declared virtual environment, lint or type check. Placing the CLI in the register repo means its required tests have no runner and the "run against current repository" evidence has no home. Recommend adrl-core under tools with tests under tests, taking a register path argument like the W0 runner. State this assumption in the packet. Every register-facing scope decision then lives in one JSON config committed to the register repo and read by the tool.

- **B6. Match keys for INDEX, bucket overview and CHANGELOG are unspecified and cannot be finalized from the supplied inputs.** The runner only checks INDEX row set equality. The plan needs a concrete rule: the ADR changelog table has a row dated today, the register CHANGELOG has an entry naming the same ADR IDs and the same closure record link, the bucket overview names the ADR ID with the same date, and INDEX status and maturity columns equal the ADR table rows. The implementer must read the actual INDEX and bucket overview formats first, since neither was supplied. Reuse the runner's index regex to avoid divergence.

- **B7. Unexplained register changes must fail, not just unmapped implementation files.** As specified, a stray edit to an unrelated ADR during the wave is invisible. Require that every changed register file is one of: an owning ADR named in the closure, INDEX, CHANGELOG, a bucket overview of an owning ADR, this closure's evidence record, or the reviewer record. Anything else fails with a named reason. Preexisting dirt relative to git head is reported in the receipt as informational, never attributed and never silently laundered.

## Non-blocking findings

- **Maturity guard scope.** Diff the Maturity, Status and Review verdict rows, not Maturity alone. The referenced human record needs a fixed shape: path under reports, ADR ID, old and new value, reviewer name, date. Attestational only.
- **Review pending is a failure, by design.** A closure check without a reviewer record exits nonzero with reason `review_pending`. This is not an approval request. The author fixes everything else first, then requests review once.
- **Mirror verification.** Home-directory skill copies are outside both repos, so they cannot be symlinks under the escape rule. The check reads them from configured absolute paths and fails on any byte difference or absence. Canonical copy lives in the register repo.
